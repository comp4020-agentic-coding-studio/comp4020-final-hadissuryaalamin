# Crit 10 — Fly by instruments

**Breakthrough.** The app worked, but it looked like every other generated
admin panel, and asking the agent to "make it look better" only gave me
another version of the same thing. So I asked a friend how to make a UI that
doesn't look like AI slop. They pointed me to mkdir.directory, and from there
I browsed and found stayor.framer.website, which I gave the agent as the look
to follow. That was what moved it forward: a real page is a target, an
adjective isn't. It suited this app: the business is short-stay
accommodation, so the look should feel calm and clean. I still had to
correct it. I checked every page in the browser myself, accepted the
restyle, and then said the chat page was ugly. I approved a mock before it
was rebuilt, instead of reacting to something already built.

The design checker then flagged the new font and cream background as
overused, the kind of choice AI tools make by reflex, even though both came
from the reference I chose. I agree it is still a bit slop. But it is
acceptable: it is clean, readable, and good enough to put in front of real
users, which is what this app is for.

**What this changes about who I want to be as a developer.** I want to bring
a concrete reference when I ask for design, not a feeling. When my own eye
isn't enough, I'll ask a person and credit them. And I want to judge a UI
where a user meets it, in the browser, because green tests say nothing about
how it looks. For this app that matters: the README says a cleaner should
see what's theirs at a glance, so readable is part of "good", not polish.
