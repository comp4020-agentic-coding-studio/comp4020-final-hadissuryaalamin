# 002 — Auth & sessions

Built `src/auth/`:

- `password.ts` — `hashPassword`/`verifyPassword` via `bcryptjs` (pure JS,
  chosen over native `bcrypt` to avoid a second native addon build alongside
  `better-sqlite3` in the Alpine/slim Docker image).
- `session.ts` — hand-rolled signed session token using Node's `crypto`
  (`createHmac`/`timingSafeEqual`), format `<base64url-json>.<base64url-hmac>`,
  signed with `SESSION_SECRET`. Chose this over `@fastify/secure-session` /
  `@fastify/cookie` to keep the module dependency-free and testable without
  a running Fastify instance (task 006 hasn't landed yet). Also exports
  `readSessionCookie` (parses the raw `Cookie` header — no cookie-parsing
  plugin needed) and `buildSessionCookieHeader`/`buildClearSessionCookieHeader`
  for login/logout routes in later tasks to set/clear the cookie.
- `guards.ts` — `requireAuth` and `requireRole(role)`, Fastify
  `(request, reply)`-shaped `preHandler`s. Both read+verify the session
  cookie and attach it to `request.session` (typed via `declare module
  "fastify"` augmentation) on success; `requireAuth` 401s with no/invalid
  session, `requireRole` 401s the same and 403s a wrong-role session.
- `seed.ts` — `seedAdminIfMissing(db, env)`: no-op once any admin row
  exists, no-op (not an error) if `SEED_ADMIN_USERNAME`/`SEED_ADMIN_PASSWORD`
  are unset, otherwise hashes and inserts the seed admin. Never hardcodes a
  password.
- `accounts.ts` — `createCleanerAccount(db, { username, password })`: hashes
  the password and inserts `users` (role `cleaner`) + `cleaners` (default
  `rank` `normal`) in one `better-sqlite3` transaction. Plain function only —
  no HTTP route added here; task 004's admin "create cleaner" endpoint will
  call this.
- `index.ts` — barrel export of all of the above.

Dependencies added: `fastify` (for guard/types only — no server instantiated
in this task) and `bcryptjs` (ships its own `.d.ts`, no `@types/bcryptjs`
needed).

## Tests (`src/auth/*.test.ts`, colocated, `pnpm test:unit`)

- `password.test.ts` — correct password accepted, wrong password rejected,
  hash doesn't contain the plaintext.
- `session.test.ts` — round-trip, tampered-token rejection, wrong-secret
  rejection, malformed/missing input, `readSessionCookie` parsing.
- `guards.test.ts` — `requireAuth` rejects no session (401) and accepts +
  attaches a valid one; `requireRole('admin')` rejects no session (401),
  rejects a cleaner session (403), accepts an admin session.
- `accounts.test.ts` — inserts both rows with a verifiable hash, rejects a
  duplicate username.
- `seed.test.ts` — seeds from env vars, is a no-op once an admin exists, is
  a no-op when env vars are missing.
